# ADR-001: set_hash рахує dataset manager над канонізованими кейсами прогону, а не над байтами файлів

Status: accepted

Context
  Кейси лежать у файлах `sets/*.jsonl`. Один прогін бере кейси з кількох
  файлів, а фільтри GATE і CASE змінюють перелік кейсів без зміни файлів.
  Файли перезберігаються редакторами і клонуються на Windows з CRLF;
  порядок рядків і ключів JSON може змінюватися без зміни змісту.
  Записи прогонів порівнюються між машинами і між днями, тож поле
  `set_hash` має збігатися тоді й лише тоді, коли збігається вміст кейсів,
  що пішли в прогін. Старий `loader.set_hash(path)` хешував байти одного
  файлу. Еталонні значення хешів задані темою і звіряються.

Decision
  Ми рахуємо `set_hash` у dataset manager (`run_eval.set_hash(names, ids)`):
  sha256 (перші 12 символів) від канонізованого JSON кожного кейса
  (`sort_keys=True, ensure_ascii=False, separators=(",", ":")`),
  відсортованих за id кейсів, що пройшли фільтри GATE/CASE; склейка через
  `\n`. Ранер отримує готовий список кейсів і хеш та не читає файли наборів.

Consequences
  + хеш описує саме ті кейси, що пішли в прогін, а не файли цілком;
  + стабільний до CRLF, перезбереження, порядку рядків і ключів;
    збігається з еталоном (`l03` → `2eeadf91c793`, щоденний шар →
    `58cf5b498718`), тож «набір не змінювався» перевіряється одним рядком;
  − файли наборів читаються двічі (`_raw_cases` для хешу і `loader.load`
    для прогону), і хеш не можна порахувати без усіх файлів набору;
  − канонізація зафіксована жорстко: будь-яка зміна серіалізації змінює всі
    хеші (це вже сталося під час звірки з еталоном — стару форму без
    `separators` замінили).
  Переглянемо, якщо набори переїдуть із файлів у реєстр (БД) або виростуть
  настільки, що подвійне читання стане помітним у `--dry-run`.

Alternatives
  Хеш байтів файлів — ламається від CRLF і перезбереження, не бачить
  фільтрів GATE/CASE. Git-коміт набору — не бачить незакомічених правок і
  фільтрів, прив'язує контур до git. Хеш від переліку id — не бачить правок
  змісту кейса (саме це мала показати перевірка «виправлений кейс змінює хеш»).
